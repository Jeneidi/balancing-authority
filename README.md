# Beat the Balancing Authority

A day-ahead electricity demand forecaster scored head-to-head against the grid operator's own published forecast on public EIA-930 hourly data, with an honest prediction interval.

Live demo: https://balancing-authority.mjeneidi.com

## The problem

Utilities and grid operators live by day-ahead load forecasts. A student model is only credible if it is scored against the forecast the balancing authority actually publishes, not a strawman.

## The result

The generated site reports real held-out MAPE, 95% bootstrap confidence intervals over days, win rate against the operator forecast, same-hour-last-week error, and 90% interval coverage for FPL, Duke Energy Carolinas and TVA. The exact numbers are generated by `scripts/run_experiment.py` and committed to `site/data/results.json`.

## How it works

1. Download five official EIA-930 six-month balance files and archived Open-Meteo Previous Runs weather forecasts.
2. Build hourly rows with calendar features, demand from 24 and 168 hours earlier, and the temperature forecast issued one day earlier.
3. Train one LightGBM gradient-boosted model on 2024 and 2025 H1, validate on 2025 H2, and score 2026 H1 without shuffling.
4. Compare the model with the operator's day-ahead forecast and same-hour-last-week baseline.
5. Derive a 90% prediction interval from the 5th and 95th percentiles of validation residuals, then check coverage.

## Data and license

- EIA-930 Hourly Electric Grid Monitor: https://www.eia.gov/electricity/gridmonitor/sixMonthFiles/. US government data, public domain.
- Open-Meteo Previous Runs API: https://open-meteo.com/en/docs/previous-runs-api. Archived weather forecasts, CC BY 4.0 attribution required.

## Evaluation method

The headline metric is MAPE on 2026 January through June. Confidence intervals are 1,000 seeded bootstrap resamples of daily MAPE. The time split is train through 2025-06-30, validation from 2025-07-01 through 2025-12-31, and test from 2026-01-01 through 2026-06-30. The unit test asserts that the weather feature issue timestamp is no later than the target issue time.

The project is intentionally traceable. The same evals discipline is useful for LLM agents, RAG and MCP systems, while energy teams can extend the pipeline toward anomaly detection, predictive maintenance, smart meters and NRC licensing traceability.

## How to run

```bash
uv venv .venv --python 3.11
uv pip install --python .venv/bin/python -r requirements.txt
.venv/bin/python scripts/download_data.py
.venv/bin/python scripts/run_experiment.py
.venv/bin/python -m pytest -q
cd site && python3 -m http.server 8000 --bind 127.0.0.1
```

The raw EIA files are larger than 20 MB and are ignored by git. The download script recreates them and caches the weather responses.

## Limitations

The operator forecast is published for the current day, so this project treats the EIA forecast column as the operational comparison rather than reconstructing its original publication timestamp. The weather feature uses Open-Meteo's documented `temperature_2m_previous_day1` field, which represents the forecast made 24 hours before valid time. The model uses one location per authority, and the validation residual percentile band is simple rather than conformal.
